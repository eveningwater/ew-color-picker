Introduction ​

ew-color-picker is a modern color picker built around two ideas:

  1. Event-driven — every action becomes an event (change, sure, clear, toggle, mode-change, options-update, destroy).
  2. Plugin-based — the core owns color state and mount points; every piece of UI is a plugin.
text
Core (@ew-color-picker/core)
├─ color state: currentColor + hsvaColor
├─ event bus: on / once / off / trigger / emit
├─ mount points: root + panelContainer
└─ plugins: can be registered, replaced, or extended

Why a plugin architecture? ​

BenefitWhat it means
Small bundlesInstall only the plugins you use
Replaceable UISwap the panel, input, or buttons for your own implementation
TestableEach plugin can be tested in isolation
ExtensibleAdd features without touching the core

Design principles ​

PrincipleDetail
Single source of truthOnly core.setColor() changes color; plugins never call each other directly
Instance isolationEach instance has its own event bus, DOM and plugin instances
No global pollutionCSS is scoped by class names; the only global is the UMD window.ewColorPicker
Progressive disclosureDefaults work out of the box; every plugin exposes options and methods when you need them
